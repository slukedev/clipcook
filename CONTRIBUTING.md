# Contributing to ClipCook

Thanks for helping. This guide covers running the app, how the code is organized, and what a good pull request looks like.

## Run it locally

You need Node 24 (see `.nvmrc`). No Firebase project is required.

```bash
npm install
npm run seed:demo
npm run dev
```

With no Firebase variables set, ClipCook uses the local backend: data lives in `.data/clipcook.json` and you sign in as the demo cook. `npm run seed:demo` fills the library with 18 recipes, collections and a grocery list. Run it again any time to reset.

To work against Firebase instead, copy `.env.example` to `.env.local` and fill in the Firebase variables. See the README for project setup.

## Checks

Run these before opening a pull request. CI runs the same ones.

```bash
npx biome ci .
npm run typecheck
npm test
npm run test:e2e
```

`npm run test:e2e` builds the app and drives it with Playwright against the local backend.

## How the code is organized

- `src/app`: routes. Pages are server components by default; interactive parts are small client components next to the page that uses them.
- `src/actions`: server actions. Each one checks the session, validates input with zod and returns an `ActionResult`.
- `src/server`: server-only code. `db/` holds the storage interface with Firestore and local implementations. `clip/` is the recipe importer and its SSRF guard.
- `src/lib/recipe`: pure recipe logic (ingredient parsing and scaling, timers, grocery merging, text import). Unit tested in `tests/unit`.
- `src/components/ui`: the Material 3 Expressive component library. Browse it at `/dev/gallery` in development.
- `src/styles`: design tokens and SCSS mixins. Colors are generated by `npm run generate:theme`.

## Design and copy

ClipCook follows Material 3 Expressive closely. Before changing UI, read `DESIGN.md`. In short:

- Use the components and tokens; don't hard-code colors, radii or durations.
- Motion uses the M3 springs from `src/lib/motion.ts` and `src/styles/theme/motion.css`, and respects reduced motion.
- Every screen works from 320px wide up, in light and dark, with a keyboard.
- Keep copy short. Labels are a few plain words, buttons name the action, and errors say what happened and what to do next.

## Pull requests

- Keep each pull request to one change.
- Add or update tests for logic changes. Bugs in the clipper should come with an HTML fixture in `tests/fixtures/clip/`.
- Include screenshots for UI changes, phone and desktop, light and dark.
- Follow the [code of conduct](CODE_OF_CONDUCT.md).
